# AI 图片与视频素材流程

仅在⓪对应生成 API 校验通过后，于③素材阶段使用。生成素材与图库、真实截图并列；不要求每句配卡，也不要求每片都用 AI。
口播人物视频是必需输入，AI 图片 / 视频只是辅助 B-roll，不能将本片改为无人物的纯旁白片。人物与 B-roll 同屏按 host-footage.md §5 执行。

## 0. 开工先校验 API（逐能力开关）

### 0.1 首次制作：先询问配置意愿

首次实际用本 skill 制作视频时，先检查本地用户偏好及本次对话的明确选择。没有已记录选择的能力，分别询问一次：
- 「是否配置生图模型，用于辅助配图？」选项：现在配置 / 使用已有配置 / 暂不配置。
- 「是否配置生视频模型，用于辅助 B-roll？」选项同上。两题可一起展示，生图与生视频独立选择。

已配置不等于已同意启用；首次可用「使用已有配置」确认意愿。用户已明确要求使用某模型/API 时视为对应能力已选择，直接配置或校验，不再重复问。
本引导只在首次制作触发；安装、讨论流程、审阅或编辑本 skill 时不弹出。

- **现在配置**：先了解用户的服务、模型和端点，复用已提供的信息；按对应服务指引在本地设置凭据或登录，不让用户在聊天里粘贴密钥。
  配置完成后走§0.2，选择配置本身不算校验通过，也不授权付费测试或自动订阅。
- **使用已有配置**：读取用户指明的配置来源，直接走§0.2；缺少或失效就说明并关闭对应能力，用户可主动选择修复。
- **暂不配置**：关闭对应流程，不校验、不催配、不安排生成素材；使用真实素材 / 图库 / 动效卡继续制作。
- **尚未回答**：保持问题待答，不把超时当作跳过或同意；等待期间可继续稿件、人物视频等不依赖生成能力的工作，不启动生成请求。

用户偏好保存在 Codex 用户目录下的 `video-talkcraft/settings.json`（优先 CODEX_HOME，未设置则用 `~/.codex`；用户本地，独立于 skill 仓库），
按 `image` / `video` 分别记 `choice`（configure / existing / skip）、`provider`、`model`、不含凭据的 `endpoint`、
`credentialRef`（如环境变量名或配置路径）与更新时间。只记录用户确实做出的选择，保留无关字段；不存密钥、令牌或带凭据 URL。
只有当前对话的明确指令或用户之后主动要求设置/更换模型才改变偏好；已选 skip 不因换项目、API 缺失或校验失败再次弹问。
若没有权限保存，只在当前对话沿用并说明未持久化，不能声称已永久记住。旧记录缺少某一能力时只问缺的那项。
偏好用于记住意愿，不作为 API 可用性证明；每支片开工对选择启用的能力重新核验，并在 sources.md 记录本片结果。

### 0.2 已选择启用：校验后再进生成流程

用户要复用已配置的 Toonflow / ComfyUI 时，读 `toonflow-comfyui.md`，用 `scripts/toonflow_media.mjs` 引用本地适配器并预检，不重建工作流。

生图与生视频分别校验，不能因为一个可用就推定另一个也可用。只检查当前明确配置的服务，不扫描或打印密钥、不要求用户在聊天里提供密钥。

1. **配置**：确认服务端点、凭据或登录态，以及目标模型/能力有明确配置；仅发现某个 skill、CLI 或工具名称不算 API 可用。
2. **连接与鉴权**：优先用服务提供的只读健康、账户、权限或能力查询接口，验证可达、鉴权有效以及目标生图/生视频能力可调用。
   通用模型列表或健康接口成功不等于特定模型有调用权限；额度/配额能查询时也须确认。无证据的状态记「未验证」，不能记通过。
3. **必要的生成探测**：若只读接口无法确认实际能力，只在用户已有生成测试授权与费用范围内做最小测试，验证任务成功且产物可读取。
   不能为体检擅自产生费用；没有授权或无法验证时，该能力保持关闭。
4. **记账**：在工程 `sources.md` 的「生成能力预检」节分别记录生图、生视频的服务、目标能力、校验时间、验证方法、
   结果（可用 / 未配置 / 不可用 / 未验证）、脱敏原因与是否启用。不得保存密钥或带凭据的 URL。

只有「可用」才开启对应流程。没有 API、失败或未验证就跳过，不创建生成任务、提示词清单或待生成占位，不要求补配置，也不把它列为未完成阻塞；
SHOTBOOK G0 简记关闭原因，镜头按真实素材 / 图库 / 动效卡设计。用户以后主动配置或要求重试时，再校验启用。
生图可用而生视频不可用时，仅允许生图及普通图片运镜；两者都不可用时完全没有 AI 生成流程。
制作中 API 失效则关闭该能力并调整受影响方案；已生成且合格的本地素材可以保留，核心画面变更仍需重新确认。

## 1. 按表达目的选型

| 要表达什么 | 优先手段 | 为什么 |
|---|---|---|
| 真实事件、某产品实际功能、新闻、来源证明 | 实拍、真录屏、真实截图 | 需要可核验的证据，不能生成替代 |
| 概念、情绪、比喻、假设场景、难以拍摄的环境 | AI 图片 | 可控制构图与风格，定格足够表达就不必生成视频 |
| 运动、变化、场景演进、需要连续动作的比喻 | AI 视频：文生视频或图生视频 | 时间中的变化本身就是信息 |
| 精确数字、逻辑关系、步骤、前后对比 | Remotion 图表 / 线稿 / 动效卡 | 数据、标签和时间可控，避免生成内容的错字与逻辑漂移 |

同镜可以组合，例如「AI 场景作底床 + Remotion 精确数字」。先写镜头要观众看懂什么，再决定媒体；卡库是可复用工具，不是所有画面的必选主角。
AI 场景直接当主视觉时，只需合适的呈现、字幕与转场，不额外叠一张无信息增量的内容卡。

## 2. 先拟素材简报，再生成

在③按语义段落写素材简报，④整合进 SHOTBOOK。每条写：对应口播、目的、图片/视频选择理由、主体与动作、环境、景别与构图、
本片风格参考、字幕/人物安全区、画幅、所需时长与剪辑余量、禁出现项。连贯镜头复用已确认参考图，保持人物、服饰、空间和光线一致。

- 图片：按画幅与最大缩放预留分辨率；需要留白就直接写进构图。文字、精确数字、logo 与标签尽量后期叠加，不烘焙进生成图。
- 视频：一条素材承担一个明确动作或变化；说明起始/结束状态、主体运动与相机运动。生成长度覆盖镜头及转场余量，不能只看标称秒数。
- 图生视频：需要构图或角色连续性时，先生成并检查起始图，再以该图生成运动；不是所有视频都必须先出图。

任务允许生成时可执行；若服务需新付费、上传敏感素材或超出用户已同意的数量/重试范围，先取得相应授权。
同一显卡上的资源串行生成（图片和视频共用一个名额），前一任务结束后才启动下一任务；不设生成等待时限，按任务编号持续等待。
本地 Toonflow/ComfyUI 由 toonflow_media.mjs 的共享资源锁执行；其他通道须有同等调度保证。异常时核远端任务状态，不因等待较慢重提任务。
默认每条先出一个候选，有问题只做针对性修订；一次修订仍不可用就说明问题并请用户选择继续、换路线或放弃，不无限抽卡。

## 3. 只使用已通过预检的生成能力

- 图片只使用§0已校验的通道；若用 `imagegen` skill，调用前读取并遵循它。不能以环境自带工具绕过 API 预检；无法核验的通道保持关闭。
- 视频用环境已启用的视频生成工具或已配置服务；例如可用时按 `higgsfield-generate` skill 的流程生成单段 B-roll，
  不把本片交给另一套整片生成器，也不在这里钉死模型名、时长枚举或价格。调用前读所用服务的技能并核当前参数。
- 不假设有账号、额度、API Key 或可商用权限。视频 API 未启用时不安排 AI 视频；仅在生图 API 已通过校验时可选 AI 图片 + Remotion 运镜，
  须称为「AI 图片运镜」。AI 关闭本身不算缺少素材，改用真实素材 / 图库 / 动效卡继续。
- 本文是素材制作协议，不是内置生成后端；仅更新此流程不触发任何生成请求或费用。

## 4. 验收、标识与来源记账

图片检查概念是否一眼可读、结构/手部/物体是否异常、构图与留白是否合适。视频还需检查全段动作连贯、身份与空间一致、
穿模、闪烁、变形、重复帧、黑帧、突兀切镜；至少核起点、过程、终点并播放预览，不能只验首帧。
生成的科学/历史示意须另核事实，不能因为画面像真的就当作正确。

AI 素材仅作示意，不能冒充实际新闻现场、真实人物言行、产品真实界面或实测效果。
涉及真实人物、事件、地点或易被误认成实拍的示意，画面可见标注「AI 生成示意」或「情景演绎」；发布披露再遵循平台要求。
纯抽象插画也须在分镜与来源表标明 AI。不得借 AI 路线绕过真截图和来源核验要求。

候选落工程 `assets/generated/`，选中后进入 `remotion/public/generated/`；生成工具若先存其他目录，复制到工程后才接入。
每次修订用版本文件名，保留已确认版本，不覆盖用户素材。
在 `sources.md` 登记每个选中资产：镜号/用途、本地路径、AI 标识、服务与实际模型、日期、提示词、参考素材来源与使用权、
尺寸、视频时长/fps/是否含音轨、已核授权或待核状态、已知限制与披露方式。没有远程 URL 的生成物记本地文件，不编造来源链接。

## 5. 进入 SHOTBOOK 审核

保持机器可读的原有类型，不把「AI」变成新媒体类型：图片仍是 `图`，视频仍是 `V`；来源与生成信息另写。

```markdown
### s03 · 12.0–18.0 · 意图：用拥堵表现信息过载
- 素材：V（public/generated/s03-overload-v1.mp4）· 文
- 来源：AI 视频，情景示意；提示词与生成记录见 sources.md
- 表达选择：连续涌入的信息让人应接不暇，AI 场景比文字逐项堆叠更直接
- 版式行：主体为视频区，口播人物角标常驻，字幕留底部安全区
- 选卡行：本镜无内容卡，AI 视频直接承担论点画面
- 蒙皮行：无内容卡 → 视频区包 ThemeFrame，按本片主题设置边框
- 语义偏离：论点 ← 由连续场景直接表达信息过载
```

示例路径必须换成实际文件，语义偏离只在确有需要时写，值应来自本镜语义标注；不得用它掩盖缺失的证据、数字、身份或号召信息。
`card_match.py` 给的是卡候选，不会判断是否该生成场景；AI 资产选定后，按原有 V / 图输入寻找必要的呈现工具即可。
图片可用 slow-push-in 等轻运镜承接，视频直接做主视觉时按现行规则包 `ThemeFrame`，不强制再套一张内容卡。
保持蒙皮行与容器说明：现有 preflight 对只有 ThemeFrame、无承接卡的镜头给 WARN，人工核实容器后保留说明，不能宣称全 PASS 或删除其他检查。

④-1 审核表须给实际生成图片/视频预览、AI 来源、表达理由和已知限制，不能用提示词或卡片 demo 代替生成结果。
生成尚未完成可先讨论草案，但不能将其记为最终确认或进入⑤；生成结果变化导致核心画面改变时，重新确认受影响镜头。

## 6. 合成与渲染

视频以本地文件接入 `<OffthreadVideo>`，默认静音，人声仍由整条配音轨负责；原生环境声只有明确选用后才另入音频设计与验收。
检查实际时长、fps、像素尺寸与编码可解码；按选定 in/out 截取，避免无意循环或冻结尾帧。
生成 B-roll 可按已知源帧率规范转码并核重复帧；人物口播仍遵守 host-footage 的音画同步与帧率规则，不能混为一谈。
生成视频已有明显运镜时，不再叠加冲突的外层相机运动；在 SHOTBOOK 写明该镜运动由源视频承担，渲染后仍需过画面健康检查。
图片走 `<Img>` 与轻运镜；字幕、精确标注和词锚仍由 Remotion 控制。生成视频内部动作不天然字级可控，
关键动作未对上词锚时应重选 in/out 或调整素材，必要时重生成，不能仅在 beats.json 宣称对齐。
现有素材预检、分段渲染、音画时长检查及三重验收照常执行；预检识别到 V / 图并不代表已经验证生成质量或来源真实性。
